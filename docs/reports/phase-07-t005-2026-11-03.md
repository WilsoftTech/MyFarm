Adds additive migration `202611030001_record_photos`, runtime policy `offline-photos-runtime.sql`, the photo service and routes, the command dispatcher, and `GET /api/v1/sync/pull`. Commands go through the existing services, so their authorization, validation, receipts and atomic writes still apply. The command's own ID always becomes the request ID, whatever the payload claims. `recordDone` records finished work in one transaction, so a retry cannot leave it half recorded.

**Photos (D-P07-004):** the upload checks the actual bytes, size and digest, then stores the object with the member's own session under a new tenant-prefixed storage policy, so no privileged key enters the app. The network call stays outside the database transaction, and a failed upload leaves no row or receipt and can be retried. Rows are append-only, and a database check enforces one parent record, a 2 MB limit and allowed types. Links for viewing use the existing audited private file grant.

**Pull:** each page goes through the list services farmers already use, so nothing new decides what they may read. Records are only appended or change status, so deletion markers and the proposed change log, with its risk of skipping late commits, are not needed. An expired cursor returns `EXPIRED` so the phone can restart, a forged one can reach only what the account may already read, and a farm whose access ends is skipped. An account with no farmer profile gets an empty result.
