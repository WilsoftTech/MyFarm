## Delivered scope

- Enterprise detail displays production actions from the authorized T011 `workflow` capability. A small `EnterpriseWorkflow` component replaces the nested enterprise-type conditional, reusing existing Button/Link styling. Supported active enterprises retain their start and history links; closed supported enterprises retain history only. Unsupported types display the existing explanation with no production action links.
- Enterprise list cards now explain that production records are unavailable for unsupported types before the farmer opens the detail screen.
- Crop and poultry choices use one `enterpriseChoice` presentation helper for initial pages, subsequent pages and deep-linked presets. It consumes the service capability, labels unsupported/other-workflow/closed choices and disables them. An unavailable preset stays visible but is not preselected for submission. Farmer-entered values and existing pagination/error/loading/reconnect behavior remain owned by the existing forms, ChoiceField and useProductionSubmit.
- Component tests cover keyboard links, scoped URLs, closed enterprise history, unavailable states and choice feedback. Action tests verify that presentation follows the service capability rather than a second enterprise-type registry. The browser acceptance cases plant all 12 released crops using the same form and check all four unsupported types on details, lists and both selectors, including a preset beyond page one. Released crops also exercise offline reconnect and lost-response replay through the existing regression cases.

Important files: `components/production/enterprise-workflow.tsx`, `enterprise-choice.ts`, `crop-choices.ts`, `poultry-choices.ts`; enterprise list/detail and crop/poultry new pages; `tests/component/enterprise-workflow.test.tsx`, `tests/unit/production-actions.test.ts`, `tests/browser/crop-cycle-ui.spec.ts`.
