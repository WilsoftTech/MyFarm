Adds `POST /api/v1/sync/push`, `PushService` and the client sync engine. Each command runs alone through the existing services, so one refusal cannot undo another's committed effect. Each returns one outcome: committed, retryable, conflict with the current record, invalid or denied. Unexpected failures are retryable. A malformed command is reported on its own so it cannot block the queue behind it. A session that ends mid-batch fails the whole request, and anything already committed replays from its receipt.

The engine runs one sender per account across tabs with the Web Locks API; leases and server receipts still protect browsers without it. It recovers abandoned sends, takes leases in a transaction, sends parents before children, uploads photos, removes a photo's local copy only after the server confirms it, and pulls fresh copies after sending. A whole-batch refusal leaves every entry queued rather than marking each as refused. A photo whose bytes the browser lost is shown as failed rather than retried forever.
