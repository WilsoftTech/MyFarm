Successful reads/writes use private, no-store caching; failures are no-store.

## Integrity and concurrency

The unique audit receipt key serializes identical requests. The repository rechecks account and farm/tenant membership before/after claiming the receipt. A replay reads its original scoped cycle and compares every normalized creation field and actor before returning it. It does not allocate area again. Reusing the request with a different farm or payload conflicts. A catalog-name snapshot preserves historical/retry labels even after catalog renaming or deactivation; replay still requires current authorization. Future commands that edit creation fields must review this receipt compatibility before rollout.

New starts acquire `pg_advisory_xact_lock(hashtextextended('myfarm:crop-plot:' || plotId, 0))` inside a Read Committed transaction, then recheck authorization and resolve scoped enterprise/season/plot and the catalog crop. All starts take receipt then plot lock in that order. Transaction-scoped locks release on commit/rollback and require no new Plot UPDATE privilege. A hash collision serializes unrelated plots without weakening capacity checks. The transaction timeout is 10 seconds; timeouts roll back and return a safe retryable failure. No external network calls occur inside the transaction.

The complete ACTIVE allocation set for the plot is loaded without pagination or enterprise/season filtering and passed to T004's exact BigInt area rule. Expected harvest never releases capacity. Unknown plot area, mixed units, wrong/closed parents and inactive catalog entries fail. Excess area requires a recorded reason, saved with the actor/date/scope and audit receipt. A final membership check precedes the insert, and row plus audit commit atomically. Independent starts competing for 0.6 of a 1-acre plot produce one success, one validation failure, one cycle and one audit effect. Six simultaneous identical starts produce one cycle/receipt, including a full-plot retry.

Three composite FKs `(parentId, farmId, tenantId)` prevent cross-farm/tenant enterprise, season or plot links independently of application code. Restrictive deletion preserves referenced histories. CHECK constraints enforce positive finite supported area, versions, nonblank text and finite ordered dates. Numeric storage has six fractional digits; untrusted overprecision is rejected before SQL rather than relying on PostgreSQL's numeric rounding.

As in the existing shared runtime architecture, SELECT policies are `USING (true)` for the server role; application authorization and query predicates enforce read isolation. INSERT policies check actor/parent consistency, not the identity of an HTTP caller. Capacity serialization is an application repository guarantee, not a database trigger guarding arbitrary privileged SQL. Future closure, plot-area changes and other allocation writers must coordinate with the same plot lock. Account/membership checks use current statement snapshots; no global guarantee for revocations committed after the final check is claimed. Browser roles cannot access the application tables directly. No security-definer function or new privileged service was added.
