## Changes

`FieldPilotService` (`src/modules/field-pilot/application/pilot.ts`) and its Prisma repository:

- **Farmers** join with a cohort code, list their own participations and withdraw. A wrong, closed or ended code looks the same as a missing one, so codes cannot be probed. Only an active farmer may join. Joining again while in the pilot is harmless; after withdrawing, joining again is refused. Pseudonyms are P-01, P-02… in joining order, with a retry if two farmers join at once.
- **Staff** (ADMIN of the organization in the path) open cohorts, see a cohort's live measures, pseudonyms and incidents, and log prompts, incidents, resolutions and paper consent. The server chooses the cohort code (8 characters, no 0/O or 1/I) and the consent version. A cohort of another organization looks missing.
- **Every write** claims a receipt, so a repeated request returns the first result; version checks stop stale changes.
- **Measures** are worked out on each request from receipts and logs (no stored figures), bounded to the cohort's farmers and window.

**Usage log (D-P09-008).** `PushService` takes an optional usage log. After each push it records one row per entry: committed, or refused (invalid, conflict or denied). Retryable server failures are not counted, because the phone retries them. The row goes into the tenant of the farm the farmer belongs to; an entry for a farm they do not belong to is not logged. A failure to log is recorded under code `PILOT_USAGE_LOG_FAILED` and never fails the sync.

Routes, all private and same-origin for writes:

| Who | Route |
|---|---|
| Farmer | `GET`/`POST /api/v1/pilot/participations`, `POST /api/v1/pilot/participations/{id}/withdraw` |
| Staff | `GET`/`POST /api/v1/scopes/{scopeId}/pilot/cohorts`, `GET .../cohorts/{cohortId}`, `POST .../prompts`, `POST .../incidents`, `POST .../incidents/{id}/resolve`, `POST .../participations/{id}/paper-consent` |
