It adds a nullable `AccountingRecord.batchId` with a same-farm composite foreign key and index, and a nullable `TransactionCategory.costGroup` with a check that only cost categories hold one. It seeds the seven approved groups by ID, so category names stay out of application code. `farm-accounting-runtime.sql` now allows a batch link only on an expense or purchase naming the batch's own enterprise.

**Rollback:** the migration is one transaction, and a test proves a failure leaves nothing behind. Both columns are nullable, so earlier application code keeps working. Hosted use needs this migration and a rerun of the runtime policy, which is a separate owner step.

## Choices to review

- **Date ranges:** per-acre and per-kg figures are not available in a date-range view, because it holds part of a cycle's costs but all of its acres. This is an engineering choice within D-P08-007.
- **Whole-life batches:** batch figures ignore the chosen season or dates, as the catalog states, because batches have no season.
- **Zero numerators:** revenue of 0 on known acres shows a real 0 per acre. Only a zero or missing denominator is "Not available".
