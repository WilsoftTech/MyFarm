Adds the offline work screen: all six write actions, cached farms and records, status per entry, photo capture with compression, and the first pull of cached data when a signed-in page opens. Entry forms use the server's own validation, so bad values are refused before saving. Activity choices follow the same crop and poultry rules as online, and a harvest takes its crop and plot from the cached cycle. Saved copies state their date and that they may have changed since. Offline sale stays online-only.

Saves report success only after the IndexedDB transaction commits, and a photo and its entry commit together. Pull writes pages as they arrive and replaces older rows only when the whole snapshot is in, so an interrupted pull never loses saved copies and never touches unsent entries. The local database code loads on demand, so ordinary signed-in pages do not carry it.

**MYF-P07-AC001 and AC002 are verified locally.** PASS on desktop and mobile with the app server really stopped: the shell opens cold; expense, income, harvest, activity, task and photo each save; invalid values save nothing; all six entries survive a reload as `PENDING` with a device ID, timestamps and version; the photo keeps its bytes, digest and link to its parent; cached farms and records display. A full phone shows "Not saved", keeps the farmer's input, stores nothing, and saves on retry. Typecheck, lint, boundaries and fixture build pass.

**Simulated:** the full-phone test makes the browser's storage call raise a real `QuotaExceededError`, because Chromium's quota override did not reliably fail a small write. A truly full device has not been tested. Sending to the server starts at T008.

The browser tests also found a real bug, now fixed: cached rows were keyed by section and ID, so global categories from a second farm overwrote the first farm's, and an account with two farms lost those choices on one of them. The key now includes the farm.
