## Rules and limits

- **Bird counts** are whole numbers (D-P03-003) and nonnegative (AC003), so a starting count of 0 is accepted. Commands use digit-only strings, matching the decimal-string convention of crop area. Signs, decimals (including `1.0`), exponents, separators and hexadecimal are rejected rather than rounded. Leading zeros normalize (`000300` → 300). The upper bound is the PostgreSQL `integer` maximum (2,147,483,647), the column type proposed in phase F.
- **Parent:** the enterprise must match the authenticated farm/tenant and requested ID, be POULTRY and be ACTIVE, reusing the T001 rule. The other five enterprise types fail, so the "workflow not yet available" behavior holds for them.
- **Batch identity** is the server-generated batch ID. Batch name, animal type and purpose are required free text (1–120 characters); breed is optional. No uniqueness is imposed on batch names, because none was approved. The repository contract requires distinct requests to create distinct batches and identical retries to replay; that is proved against the database in T008.
- **Animal type** is free text. D-P03-003 only places crops in a data catalog; no animal-type catalog was approved, so none is invented.
- **Acquisition date** must be a real `YYYY-MM-DD` date. No past/future restriction is imposed, consistent with crop planting dates.
- **Current quantity** is derived by `currentBatchQuantity`, never stored or overwritten (AGENTS §9). In Phase 3 there are no bird movements, so it equals the starting count with source `STARTING_QUANTITY`. Phase 5 adds append-only movements and further sources.
- Poultry batches link only to an enterprise, as in the phase F proposal and the T001 links schema; there is no season or plot link.

## Repository and persistence boundary

T007 changes no Prisma schema, migration, provider grants, service, API or screen. As with T004, the pure contract needs no database object. The `LivestockBatch` storage subset is reviewed in T008.

The `PoultryBatchRepository` port defines farm-scoped single/list reads and a start command. Its documented T008 obligations are: current membership recheck and enterprise resolution inside the write transaction, reuse of `assertPoultryBatchStart`, atomic batch plus audit receipt, identical retries replaying and changed retries conflicting, distinct requests creating distinct batches, full rollback on failure, and a derived current quantity. These guarantees are a contract only; no runtime idempotency, authorization or database constraint is claimed for poultry batches.
