## API contract

| Method and path | Result |
|---|---|
| `GET /api/v1/farms/{farmId}/animal-types` | `{ items: [{ animalTypeId, name }], nextCursor }`; active global catalog, newest first (Chicken, Duck, Turkey, Guinea fowl), after farm authorization |
| `GET /api/v1/farms/{farmId}/poultry-batches` | `{ items: PoultryBatchView[], nextCursor }`, scoped by tenant and farm |
| `GET /api/v1/farms/{farmId}/poultry-batches/{batchId}` | `{ batch }`; unknown and foreign nested IDs both 403 |
| `POST /api/v1/farms/{farmId}/poultry-batches` | T007 strict start payload; 201 `{ batch }` for a committed creation or identical replay; 409 for a duplicate farm label or a changed replay |

The view carries `startingQuantity`, `currentQuantity` and `currentQuantitySource: "STARTING_COUNT"`. The current count is derived on read and is never stored or accepted from clients. Errors return only the existing safe code/request ID envelope. All responses are private and no-store.

## Integrity and concurrency

- **Receipt and authorization:** the command claims the audit receipt first and rechecks account, farm and tenant membership before and after it.
- **Replays:** a replay compares every normalized creation field and the actor before returning the original row. The display label must match exactly, so a retry with different capitalization is a changed payload (409).
- **Parents and catalog:** the enterprise and catalog entry are resolved inside the transaction. A foreign enterprise is FORBIDDEN, a wrong-type enterprise or unknown animal type is INVALID_INPUT, and a closed enterprise or inactive type is CONFLICT.
- **Name snapshot:** the stored animal-type name preserves historical labels and retry results after catalog renaming or deactivation.
- **Batch identity:** the unique index on `(tenantId, farmId, batchLabelKey)` covers ACTIVE and CLOSED batches. When requests compete for the same label, later inserts wait on the index and then fail; the whole transaction, including the receipt, rolls back to CONFLICT. Four competing requests produced one batch, one audit event and three CONFLICTs. Six identical concurrent requests produced one batch and one receipt.
- **Application key:** `batchLabelKey` is computed in TypeScript (NFC, whitespace collapsed, `toLowerCase`), not by a PostgreSQL expression, so database collation cannot change the identity rule. Direct privileged SQL must supply the same key. The runtime role cannot update or delete rows.
- **Bird counts:** `integer` plus `CHECK ("startingQuantity" >= 0)` bounds the count. PostgreSQL would round a fractional numeric cast into `integer` (verified: `1.5` → 2 via owner SQL), so fractions are rejected before SQL by the T007 contract; this was verified through service and API tests.
- **Read policy:** as in the existing runtime architecture, SELECT policies are `USING (true)` for the server role. Application predicates enforce read isolation, and browser roles cannot access the tables.
