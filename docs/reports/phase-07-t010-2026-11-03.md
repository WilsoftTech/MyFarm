Adds `domain/replay.ts` and records D-P07-007, which drops the proposed `MutationReceipt`, `ChangeLog` and `DeviceRegistration` tables with reasons and triggers to revisit. Existing receipts already give same-key replay and are kept permanently, which also satisfies the Q16 retention question.

Writing the contract exposed a real gap. Receipts are unique per tenant, request and action, so the same key on a different operation, such as an expense and then a task, would have created a second effect instead of being rejected. The contract defines one receipt per operation and a check that treats any other receipt on the key as reuse. T011 enforces it on the server.
