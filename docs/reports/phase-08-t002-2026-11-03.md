Adds `application/profitability.ts`, a small season repository, service wiring and `GET /api/v1/farms/{farmId}/profitability`. The service authorizes first, then parses filters, then reads. Money comes from the existing report query, which now also returns each record's season, so the dashboard and the gross margin report read the same sources. There is no schema change and no write, so no audit event or receipt applies to viewing it.

The filter gains the value `all`. Without it, a farmer with an active season had no way back to all records, because an empty choice means the default view. A specific season with dates is refused, and `all` may be narrowed by dates.

A season of another farm or tenant gets `FORBIDDEN`, the same as one that does not exist, so a guessed ID reveals nothing. The season list holds the newest 100, an engineering limit; older seasons still open by ID.

The database test reproduces the source dashboard from real records: 8,400,000 - 5,150,000 = 3,250,000 UGX, 38.7%, with the three enterprise rows matching. It also proves a record dated inside a season but linked to another stays out, an unlinked shared cost lowers the all-records surplus and is named beside the season view, and the cash view counts only money that moved. A reversal leaves the figures, a second currency stays apart, and all-records totals agree with the gross margin report.
