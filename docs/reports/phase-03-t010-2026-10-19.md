## Rules

- **Workflow availability:** one map decides which enterprise types have a production workflow. A crop cycle requires CROP_CYCLE and a poultry batch requires POULTRY_BATCH. DAIRY, LIVESTOCK, FISH, OTHER and the opposite workflow type are refused with INVALID_INPUT, and unknown runtime values have no workflow. Adding a workflow later means changing this map plus that workflow's own contract, never scattered type checks.
- **Catalog crops:** the start rule never reads the crop name. Golden cases start a cycle for Maize, each of the 12 approved crops, a local-language name and a 120-character name, all with identical results. An inactive entry conflicts regardless of name.
- **Source guard:** a test scans every non-generated `src` TypeScript file. It fails if a quoted seeded crop or animal-type name (`"Maize"`, `'Chicken'`, …) or a seed UUID prefix appears, so code cannot branch on catalog data. The only crop names currently in `src` are unquoted user-facing examples ("such as maize, coffee and poultry").
- **Releases:** additions need new stable IDs and names in canonical display form (NFC, trimmed, single spaces), 1–120 characters, and unique ignoring case and whitespace across all entries, including inactive ones. A reused ID or duplicate name is a CONFLICT; a malformed name is INVALID_INPUT. Deactivations must reference currently active entries, at most once, and not entries added in the same release. Entries are never deleted. Renames are outside a release because snapshots keep historical labels. A current catalog that already contains duplicate keys is reported as CONFLICT.
