## Changes

`domain/trends.ts` compares each crop in the chosen season with the most recent earlier season that grew it, and each poultry batch with the most recent earlier batch of the same animal type. It gives costs, per-acre, per-kg and per-bird figures, and one line per cost category, each with the earlier figure, the current figure and the change. The change is worked out from exact figures and rounded once, half-up to one decimal.

`domain/metric.ts` adds three reasons: no earlier season, no earlier batch and nothing earlier to compare with. The screen already has plain wording for each. `domain/metrics.ts` exports the shared exact totals so trends and metrics use one calculation. The formula catalog gains a Trends section. No schema change: everything comes from facts T005 already reads, plus each cycle's season and each batch's animal type and date, which T008 adds to the read.

## Choices to review

- **Which earlier side:** the most recent earlier season by start date that grew the crop, and the most recent earlier batch by acquisition date. Two batches started on one day are not compared. These are engineering choices within D-P08-007.
- **Crop sides add enterprises:** costs link to an enterprise and season, not to a crop, so a side adds every enterprise growing that crop in that season. If one of those enterprises also grew another crop then, the trend is not available, as D-P08-010 does for metrics.
- **Unlinked costs:** costs that could belong to a side but are not linked to it are shown for both sides, even in a currency with nothing linked, so the warning D-P08-007 asks for is never lost.
