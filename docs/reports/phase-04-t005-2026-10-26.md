## Behaviour verified

- **Archive through a reviewed release:** the integration test computes the expected catalog with `applyCategoryRelease`, applies the equivalent owner-side change in a transaction (`active = false`), and confirms the database matches the domain result. After archiving:
  - record detail and list views still show the saved category name, with `archived: true`
  - the category no longer appears in the picker list
  - a new record in it returns CONFLICT with no audit receipt
  - a direct runtime-role insert is refused by row-level security
  - an existing purchase in that category can still be paid, and an existing expense can still be reversed
- **Saved name wins:** if a catalog entry's name differs later, record views and the stored `categoryName` keep the name saved with the record.
- **Source categories:** all 13 source cost categories are active and listed for new cost records in the database.
- **HTTP:** a signed-in API test shows the same behaviour end to end (detail keeps "Crop sales" marked archived, the picker excludes it, a new sale returns 409 with no receipt), then restores the seed.
