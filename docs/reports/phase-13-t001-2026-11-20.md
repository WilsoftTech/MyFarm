## Changes and reuse

- `src/modules/weather-intelligence/contracts/weather.ts`: strict bounded forecast, approximate-location, farmer-stage and activity schemas; a minimal test adapter port accepting a coarse location key and abort signal, returning untrusted output. Only synthetic provenance is accepted. No precise coordinates, actor/farm IDs or domain-write handle is sent through the adapter contract.
- `src/modules/weather-intelligence/domain/weather-activity.ts`: pure evaluation with an injected clock. A current, matching test rain signal yields a labeled notice tied to the spraying task, exact scheduled farm date, approximate place, optional crop/stage and versioned rule. The output proposes review only and contains no executable rescheduling command.
- `tests/unit/weather-activity.test.ts`: 14 tests covering source behavior and failure boundaries.

Existing Zod, UUID validation, real calendar-date validation, activity types/labels, `assertSameFarm`, `farmToday` and the D-P06-002 `Africa/Kampala` calendar are reused. No new dependency, duplicate calendar implementation, database schema or persistence abstraction is introduced. No UI, API, browser storage, provider account or external request is added.

## Engineering interpretations and limits

Test forecasts declare issue, validity and expiry timestamps explicitly. The evaluator rejects future issues and expiry at the exact boundary; half-open forecast windows are matched against existing farm-calendar dates, not the machine timezone. No numerical weather threshold, live-provider refresh interval, license or stage-specific treatment rule is invented. These remain Q22 decisions before dependent production capabilities.

Missing location or timezone prevents assessment. Missing crop or stage reduces contextual specificity and is explicitly reported; no stage is inferred from planting dates. Another location's forecast, unavailable/unknown weather, closed/past work and unsupported activity types give no weather conclusion. A `NOT_EXPECTED` rain flag never means spraying is suitable. Every notice is synthetic and explicitly disclaims live agronomic advice. No task is changed, and re-evaluation does not create records.

The two input scopes are checked for the same tenant and farm. This is a domain consistency check, not online authentication or full parent authorization: T002 must resolve the farm, activity, crop and place through current authorized application services before evaluation. Live provider output and trusted policy binding are deliberately not implemented by this test-only schema.
