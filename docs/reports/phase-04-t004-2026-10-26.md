## Rules

- **Availability:** the tests read the shipped T002 migration and confirm it seeds exactly the 13 source cost categories (P0288–P0300), in source order and all active. It also seeds the 4 approved revenue categories and 3 payment methods (D-P04-005). Each source category is accepted for cost records and rejected for revenue records.
- **Ownership:** categories and payment methods are global reviewed data. The release schemas have no tenant, farm or owner field and reject one if supplied. Runtime roles cannot write catalogs (verified in T002), and there is no in-app editor in Phase 4.
- **Releases:**
  - Catalog changes ship only as reviewed data-release migrations, following D-P03-012 and applied per kind.
  - New IDs must be unique across all categories.
  - Names must already be normalized, 1–120 characters, and unique within a kind ignoring case and spacing. This includes archived entries, so saved history names never become ambiguous.
  - Archiving sets `active` to false; nothing is deleted or renamed.
  - A cost and a revenue category may share a name, because they are never offered for the same record kind.
  - Unknown, repeated or already-archived deactivations are rejected, as are unknown kinds.
- **History:** a record always shows the category name saved when it was recorded (the T002 `categoryName` snapshot). `categoryHistory` adds only whether that category is archived or no longer available. A later catalog name never replaces the saved one. An archived category is still refused for new records (CONFLICT, from T001).
- **Source guard:** application source must not contain quoted seeded category or payment-method names or the `f4040002-` seed IDs. The check is case-sensitive. "Other income" is exempt because it is also the plain label for the INCOME record kind.
