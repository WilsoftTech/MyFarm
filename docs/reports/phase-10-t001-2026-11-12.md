## What T001 adds

`src/modules/farm-intelligence/`, domain and contracts only:

| File | Content |
|---|---|
| `domain/rules.ts` | The rule catalog: keys, versions, severities, thresholds in plain words and the decisions behind them |
| `domain/batch-trends.ts` | `evaluateBatchTrends`: the three R001 trends for one active batch, with the windows and coverage |
| `domain/insight-state.ts` | The repeat rule: create, clear or leave an insight |
| `contracts/insights.ts` | Versioned evidence schema, acknowledge command, feed and repository contracts |

**Windows.** The last 28 complete farm days against the 28 before them. Today is left out because its records are usually unfinished.

**Figures**, all per bird so a change in flock size does not distort them:

| Rule | Figure | Raised when |
|---|---|---|
| FEED_COST_RISING | Feed-category cost linked to the batch × 28 ÷ bird-days, per currency | up 20% or more |
| EGGS_FALLING | Eggs per 100 birds a day | down 10% or more |
| MORTALITY_RISING | Deaths ÷ (birds alive at the window start + birds bought in it) | up 1 percentage point or more |

Birds alive on a day are the opening count from the acquisition date, adjusted by the purchases, deaths and sales of earlier days. Each threshold is compared as an exact fraction before anything is rounded.

**Coverage (D-P10-004, D-P10-006).** Each window is four blocks of 7 days.
- Eggs need egg entries on at least 4 days of every block.
- Mortality and feed cost need any batch entry on at least 4 days of every block. Feed cost also needs a Feed cost in each window, in the same currency.
- A batch under 20 birds at either window start, or acquired after the earlier window began, is not judged.

The reason for any figure that is not judged is kept, so the farmer can be told what is missing.

**Severity.** D-P10-004 approved two levels but did not say which rule gets which. Engineering reading:
- Each trend alone is a **Watch**.
- When feed cost rises and eggs fall on the same batch, one **Warning** is raised in their place, with both figures. This is the source's own example insight: "Production performance is deteriorating while costs are increasing" (P0587).
- The R002 threshold warnings come in T004.

**Repeats (D-P10-004).**
- An open insight is not raised again.
- An acknowledged one comes back only if its figure is worse than when it was acknowledged (exact comparison).
- Engineering reading: when an evaluation with enough records finds the condition gone, the insight is **cleared**. A problem that returns months later is then raised again instead of staying hidden behind an old acknowledgement.
- When the records are too thin, nothing changes.

**Evidence (AC001, domain stage).** Each insight stores versioned JSON: batch label, both windows, the coverage of each block, and each figure's earlier and current values, change and exact change. With it go the rule key, rule version and severity. Reading the evidence back validates it against the schema.

## Proposed database subset for T002 (F)

The phase spec's F section is a proposal. Engineering proposes building less than it lists:
- **One table, `FarmInsight`:** farm scope, batch, rule key and version, severity, currency, status (OPEN, ACKNOWLEDGED, CLEARED), the date it was evaluated on, evidence JSON, acknowledgement time and actor, and version. Add a unique index allowing one live insight per batch, rule and currency, so two requests at once cannot raise it twice.
- **No `RuleDefinition` table:** the rules are versioned code, and no one edits them at run time.
- **No `RuleEvaluation` table:** evaluations are recalculated from the farm's records whenever the feed opens.

The migration, runtime policy and repository come in T002.

The 18 new tests cover:
- The golden example: feed +24%, eggs −12%, deaths +1.4 points, which raises the combined Warning and a mortality Watch.
- Evidence round trip, and refusal of an unknown evidence version.
- Sparse records: thin egg days suppress eggs only, and thin recorded days suppress feed and mortality.
- A recorded day without deaths counts as zero deaths.
- Inclusive thresholds at exactly 20%, −10% and 1 point, with values just short of each not raised.
- Too few birds, a batch too young, one currency at a time, broilers without eggs.
- A closed batch, bad input refused, deterministic output.
- Every branch of the repeat rule.

Integration and browser suites were not run, because no database or UI code changed.
