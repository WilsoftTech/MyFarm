## Scope delivered

`src/modules/harvest-inventory/contracts/harvest.ts` defines strict harvest input, scoped view and repository contracts. `domain/harvest.ts` defines exact numeric(18,6)-compatible quantities, relationship checks and deterministic harvest reconciliation. No route, persistence adapter, UI or migration is added in this domain stage.

The owner approved kilograms, six-decimal quantities, whole birds/eggs, no conversions and no negative stock; named same-farm storage, optional grade, separate loss and deferred valuation; and one atomic stock/accounting sale with one bird effect (D-P05-002/003). Poultry and sale implementation remain dependent tasks.

Harvest input supplies gross `quantity` and separate initial `lossQuantity` (zero by default). The stored amount is gross minus loss; all-loss harvests retain the gross/loss history and yield zero. Grade is optional text up to 120 characters. Dates cannot precede the referenced planting date. The cycle supplies crop identity and must match the selected plot; cycle, plot and storage must all match the authorized tenant/farm. Named storage is required. Historical cycle references do not reopen a cycle or season; no lifecycle status mutation is exposed. Future estimates do not impose an unapproved calendar cutoff.

The T002 port requires atomic gross/loss effects, audit/receipt, current membership checks and payload-bound retries. Later corrections/losses append history. Harvest creates no accounting income. Actual storage creation, persistence and correction commands are not implemented by a TypeScript interface. Full AC001 remains pending T002/T003 and stock-linked sales; pure arithmetic alone does not establish the full user journey.

## Reuse, integrity and limitations

Reuses installed Zod, UUID validation, agricultural date validation, farm-scope relationship checks, existing decimal syntax validation, shared errors and production pagination/write metadata. No dependency added. Quantities use bigint scaled by one million; neither money nor quantities use floating-point arithmetic. The source oracle `2400 - 1600 - 150 = 650` passes without combining the separate ledger example into it.

Tests reject forged server-owned fields, malformed quantity/date/ID inputs, incompatible units, mismatched nested references, cross-tenant and same-tenant cross-farm parents, excess losses and negative remaining stock. They cover six-decimal and maximum precision boundaries. These are domain checks, not proof of authentication, RLS, atomic writes or concurrent-stock enforcement; those require real database tests in dependent stages.
