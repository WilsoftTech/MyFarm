## Implementation and reuse

- `src/modules/voice-experience/contracts/drafts.ts`, `application/drafts.ts`, `infrastructure/draft-repository.ts`, `services.ts` and `http.ts`: strict schemas, authorized service and transaction-backed repository/API.
- `prisma/schema.prisma` and `prisma/migrations/202611190001_voice_expense_drafts/migration.sql`: one additive `VoiceExpenseDraft` table. A completed row is also the immutable confirmation receipt; a separate confirmation table or audio model is unnecessary.
- `supabase/policies/voice-experience-runtime.sql` and `supabase/provisioning.json`: least-privilege server grants, membership-checked writes and browser denial, before the existing final browser lockdown.
- `src/modules/farm-accounting/infrastructure/repository.ts`: extracted the existing reference/domain validation into `validateAccountingRecord` and exported the existing batch-enterprise normalization. The writer reuses the same validation; accounting rules and arithmetic were not duplicated.
- `src/modules/farm-export/domain/catalog.ts`: the export includes only the requesting actor's active drafts/completed receipts; hashes, mutation IDs, versions and other people's reviews are excluded. Test cleanup deletes synthetic draft rows before their referenced records.

The API is `POST /api/v1/farms/{farmId}/voice/drafts`, `GET/PATCH .../drafts/{draftId}` and `POST .../drafts/{draftId}/confirm`. Existing same-origin JSON checks, private response headers, lazy anonymous denial, SAVE request limits, current session/farm authorization, money schemas, domain validation, accounting writer and audit receipts are reused.

Saving validates the currently selected category, date and links and posts no expense or stock movement. The batch's enterprise is resolved before the review is hashed. The hash binds schema version, actor, tenant, farm, draft version and the canonical full review, including the stable accounting mutation ID and descriptive bags. UUID mutation keys are normalized before persistence.

Edits require the expected version, preserve the original expiry, increment the version and issue a different hash. Identical edit retries are safe; competing different edits conflict. Confirmation accepts only explicit boolean true, the original mutation ID, current version and exact hash. Extra amount/scope/actor fields are rejected.

Confirmation locks the actor/farm-scoped draft, rechecks current access after the wait, checks expiry on the database clock and commits the ordinary expense, accounting receipt, completed draft and confirmation audit together. It rechecks the deadline after accounting/receipt waits too. The database enforces exact expiry, coherent confirmation state, same-farm/tenant record references, unique record attachment and immutable completed drafts. Five concurrent confirmations replay one result. An identical completed replay remains available after expiry, subject to current authorization; it creates no new expense.

## Findings corrected during verification

1. Prisma's automatically populated creation timestamp and PostgreSQL's expiry default differed. Both creation and expiry now derive from one database-clock reading, preserving the exact 30-minute constraint.
2. TypeScript caught a missing edit-audit mutation ID and test literal/header types; these were corrected.
3. PostgreSQL applies UPDATE visibility to SELECT FOR UPDATE. Filtering completed/expired drafts out of that policy prevented successful replay after lock waits. Lock visibility now permits retrieval; the immutable-state trigger independently refuses every actual update to completed/expired drafts, and the write policy still checks current membership.
4. An early failed test left one unreferenced synthetic catalog category. It was removed only from the explicitly guarded local test database; the fixture now tracks and cleans up its custom categories.
5. The historical crop-release fixture stopped before the voice table existed but applied the new provider file. Its existing list of later provider files now includes the voice policy; full current provisioning still applies it and is tested transactionally.
6. PostgreSQL represents the interval default as `00:30:00`. The Prisma declaration now matches that canonical representation. No applied migration was edited to conceal drift.
