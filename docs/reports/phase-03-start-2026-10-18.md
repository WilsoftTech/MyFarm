## Security and migration implications

Strict command schemas reject client-supplied actor, tenant, farm, status and version fields. Domain tests reject cross-tenant/cross-farm links and substituted parent IDs. Actual request authorization and IDOR protection are still pending T002; TypeScript scope types are not security boundaries.

Migration prepared: **202610180001_enterprises_seasons**. Applied only to the disposable local database. The upgrade test executes the actual three previous SQL files, seeds synthetic prior rows, injects failure into the new migration and verifies complete rollback of its tables/enums, then applies it successfully and verifies the prior farm rows are unchanged. The existing provisioning suite also verifies fresh install and rerun of the full migration/provider chain.

Deployment is additive with no backfill: old application code does not access the new tables. Browser-style roles with deliberately granted table access still see no rows and cannot insert because the new tables have RLS and no policies. The runtime role has no new grants. Before adding services, T002 must install and test reviewed least-privilege grants through the existing provider manifest. No production/hosted application is authorized merely by this report. Prefer a forward fix if a later application rollout fails; retain new tables and their records rather than dropping them. Any destructive rollback requires a verified backup and separate authorization.
