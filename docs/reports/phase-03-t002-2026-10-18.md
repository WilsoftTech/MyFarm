## Contracts and integrity

- Tenant, actor and farm come from verified account/membership data. Strict commands reject client scope, role, status and version claims. Reads constrain both farm and tenant, including nested production IDs and pagination cursors. Unknown and foreign nested IDs both return 403; unknown and foreign cursors both return 400.
- A create and its audit receipt commit in the same transaction. The existing unique `(tenantId, requestId, action)` index serializes concurrent retries. Identical normalized commands replay the original entity; changed creation fields or a different farm under that receipt conflict without returning another farm's record. No mutable receipt table or payload hash migration was introduced.
- Accounts and farm/tenant membership are checked inside the write transaction, both before claiming the receipt and after any concurrent wait. The integration race test holds an uncommitted receipt, observes the blocked request, revokes membership, releases the receipt and verifies rejection with no row or audit effect.
- New records start at version 1 and ACTIVE. No update/delete/closure API or grant exists in this task, so optimistic updates and final closure remain in their own commands. Payload matching uses creation fields; any future command that permits editing those fields must review retry compatibility before deployment.
- Seasons use date-only DTOs and explicit UTC conversion; overlapping seasons and an omitted end date persist correctly. Cursor ordering is stable across equal creation timestamps, bounded to 50 records, and never uses a foreign farm's anchor.
- The shared database role's SELECT policies remain `USING (true)`, matching the existing architecture. Application authorization and query scoping enforce read isolation. Insert policies check creator/scope consistency, not the identity of the HTTP caller. No per-request database actor context or stronger isolation architecture is claimed. Checks use normal database statement snapshots; no global guarantee about revocations committed after the final check is introduced.
